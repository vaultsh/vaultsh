# Разработка и тестирование

**🌐 Язык:** [English](../DEVELOPMENT.md) · [Polski](../pl/DEVELOPMENT.md) · [Русский](DEVELOPMENT.md) · [README](../../README.ru.md)

## Требования

- Python 3.12 или новее.
- `pip` и виртуальное окружение.
- Интернет или доверенное зеркало пакетов для установки зависимостей.
- Git рекомендуется для проверки diff и истории выпусков.

## Подготовка окружения

```bash
python -m venv .venv
# Windows PowerShell: .venv\Scripts\Activate.ps1
# Linux/macOS/Termux: source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e ".[dev]"
```

## Тесты и проверки качества

```bash
pytest -q
pytest --cov=vaultsh --cov-report=term-missing -q
ruff check .
mypy src/vaultsh
git diff --check
```

Запускайте только те проверки, инструменты которых установлены. Не сообщайте, что Ruff/mypy/CI прошли, если они не запускались.

## Принципы тестирования

- Предпочитайте детерминированные unit-тесты и официальные тестовые векторы.
- Подменяйте сетевой транспорт и ответы; тесты не должны обращаться к публичным API.
- Проверяйте отказ без обоих разрешений и при запросе Tor, когда его транспорт отсутствует.
- Тестируйте неправильный JSON, ID JSON-RPC, chain ID, количества, большие ответы, редиректы и крайние случаи URL.
- Никогда не используйте реальные фразы восстановления, приватные ключи, хранилища пользователей или токены endpoint в fixtures.
- Не называйте баланс одного адреса полным балансом кошелька без поиска адресов и gap-limit логики.

## Перед релизом

Запустите тесты, форматтер и анализатор типов, просмотрите diff, проверьте зависимости/лицензии, обновите README и changelog и честно укажите пропущенные тесты, непроверенные платформы и отсутствующий аудит.
