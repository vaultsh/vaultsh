## Поддерживаемые сети

| Ключ | Сеть | Chain ID | Актив | Доступные операции |
|---|---|---:|---|---|
| `bitcoin` | Bitcoin Mainnet | — | BTC | Баланс одного адреса и первая страница истории через Esplora |
| `ethereum` | Ethereum Mainnet | `1` | ETH | Нативный баланс через JSON-RPC 2.0 |
| `polygon` | Polygon PoS Mainnet | `137` | POL | Нативный баланс через JSON-RPC 2.0 |
| `arbitrum` | Arbitrum One | `42161` | ETH | Нативный баланс через JSON-RPC 2.0 |
| `optimism` | Optimism Mainnet | `10` | ETH | Нативный баланс через JSON-RPC 2.0 |
| `base` | Base Mainnet | `8453` | ETH | Нативный баланс через JSON-RPC 2.0 |
| `monero` | Monero | — | — | Не реализовано |

## Модель разрешения сети

Каждый сетевой вызов требует `network_requests_enabled = true` в TOML и `--allow-network`. Провайдер автоматически не выбирается. Для удалённых endpoint обязателен HTTPS; HTTP доступен только на loopback. Клиенты используют тайм-ауты и лимиты тела ответа, блокируют редиректы и не используют автоматически proxy из окружения.

## Bitcoin Mainnet / Esplora

Баланс и история относятся только к указанному адресу. История ограничена первой страницей и максимум 25 записями; это не полная история кошелька и не поиск других адресов. Данные выдаёт выбранный endpoint, они не проверяются независимо как доказательство состояния.

## EVM JSON-RPC

Перед `eth_getBalance` проверяется соответствие `eth_chainId` выбранному профилю:

| `--chain` | Ожидаемый ID | Единицы |
|---|---:|---|
| `ethereum` | `0x1` (1) | ETH / wei |
| `polygon` | `0x89` (137) | POL / базовые единицы |
| `arbitrum` | `0xa4b1` (42161) | ETH / wei |
| `optimism` | `0xa` (10) | ETH / wei |
| `base` | `0x2105` (8453) | ETH / wei |

Суммы обрабатываются целыми числами. Ответ провайдера не является доказательством состояния. Адреса со смешанным регистром должны иметь корректную checksum EIP-55.

## Явные ограничения

Не реализованы создание/восстановление EVM-кошелька, хранение EVM-ключей, ERC-20, история EVM, вызовы контрактов за пределами описанного read-only баланса, оценка gas, предпросмотр, подписание и отправка транзакций. Принимаются только перечисленные mainnet-профили. У Monero отдельная модель ключей и конфиденциальности; его нельзя считать разновидностью Bitcoin/EVM. Наличие папки адаптера не означает поддержку сети.
